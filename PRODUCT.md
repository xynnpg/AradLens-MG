# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Stack

Next.js + Tailwind, with future API routes for the Node backend.

## Users

The primary user is a city/content manager who curates important points in Arad and keeps the public listings accurate. They work from a desktop admin interface and need to move quickly between content review, user support, and service health.

## Product Purpose

AradLens helps people discover important points in Arad. The admin app is the operational workspace for maintaining those points, understanding the user base, and catching device or app failures before they affect the public experience.

## Positioning

The admin workspace connects the editorial truth of Arad's places with the operational signals of the app in one focused surface, so content quality and product health can be managed together.

## Operating Context

The first prototype is a web admin app backed by an API that is not yet built. It uses the administrator login `admin` / `administrare` and should make API-backed states easy to replace later.

## Capabilities and Constraints

- Admin login with the credentials `admin` / `administrare`.
- Overview dashboard with pending content work and service health.
- Users page.
- Important Points page for managing place records.
- Debug page showing app crashes, bugs, and device health signals.
- API integration is a future dependency; prototype data may be local and clearly structured for replacement.
- Additional features should support safe, understandable operations rather than add dashboard noise.

## Brand Commitments

The product is named AradLens. The admin interface uses a hard-edged industrial blueprint language: visible grids, cartographic markers, high-contrast typography, and restrained plum accents.

## Evidence on Hand

The supplied visual reference is https://binarysquad.club/. No API, logo, imagery, or production content assets are available yet. Do not fabricate external proof or live data claims.

## Product Principles

- Keep the next useful action obvious.
- Treat place data as editorial work, not just records in a table.
- Make operational risk visible without creating alarm fatigue.
- Design for confident scanning before deep inspection.
- Keep prototype data and future API boundaries explicit.
